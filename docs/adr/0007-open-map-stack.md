# ADR-0007: Open map stack — MapLibre, open basemap, vector tiles from PostGIS, Survey of India boundaries

- Status: Proposed
- Date: 2026-09-28
- Deciders: project team
- Related: docs/PLAN.md §6, §9, §11 · ADR-0005, ADR-0012

## Context

The map is the core of the product. Proprietary map SDKs bring API keys, usage costs and license lock-in, which conflicts with the DPG platform-independence indicator. International boundaries in OSM-based basemaps do not match India's official boundaries, and maps published in India must show the Survey of India boundaries. Data layers range from a handful of points to national networks.

## Decision

- **MapLibre GL JS** for rendering.
- Basemap: **OpenFreeMap** (no key) for the demo; **self-hosted Protomaps** PMTiles in production.
- Basemap boundary layers are hidden; national and state outlines come only from a **Survey of India–compliant** source.
- Data layers are **Mapbox Vector Tiles generated by PostGIS** (`ST_AsMVT`) behind a Go endpoint. Tile URLs carry the data snapshot, so caches never serve stale data. Small, per-request overlays (a pin's results) are GeoJSON.

## Consequences

- Good: no vendor lock-in or keys; one SQL query per tile; filters in SQL; CDN-friendly.
- Bad: we own the map styling; every basemap or style change needs a boundary-compliance check.

## Alternatives considered

- Google Maps or Mapbox GL — keys, cost, restrictive licenses.
- Mappls (MapmyIndia) — compliant boundaries, but proprietary.
- A tile server (Martin, pg_tileserv) — another service before any need.
- GeoJSON everywhere — breaks down for national layers.

## Revisit when

Tile traffic exceeds what the Go endpoint plus CDN caching can serve (then Martin), or an official open basemap with compliant boundaries becomes available.
